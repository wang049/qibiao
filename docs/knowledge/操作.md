# 电控条款知识库 · 怎么操作

本库只服务第 1 项出表：**认这条 DPR 是清单哪一项、别填错列**。  
抽出值来自**当份规格书**：直接写出的数，或由当份已出现的量按 `physics.yaml` 里 `derive: true` 的公式算出的缺项。  
算出的格子：抽出值写算出的数（#68 升压输出功率写 kW 点值；峰值功率括注最大电压×最大电流@时间，持续稳定功率括注最大电压×持续电流）；所用公式和代入量写在核对表 **「复核备注」**（并标局部对应）。不得把电压区间乘成 kW 范围。  
库里的示例、企标典型值不能写入核对表。不要把「符合欧姆定律」这类句子当成抽出值。当份未给出、条目在企标挂了试验方法时，抽出值仍为未检索到，复核备注写企标条款与方法号。无方法号的空项同样未检索到。仍不得写「通常」寿命或试验箱边界，也不得把「参考 标准号」写入抽出值。  
`derive: false` 的公式只用于读表/校验（例如 \(2U+1000\)、峰值\(\sqrt{2}\)有效值、\(I^2R\) 整机热损失、\(k_e/k_t\)、升压占空比）。

日常只做三件事：改卡片 → 发布 → 甲方确认后再开检索。  
知识治理由 **`.insights`（变动复盘）** 与 **wiki 锚定的相对不变量**（本目录 YAML / `published/`）共同执行；`.krow` 只放 SDK agent 自进化，不放认条复盘。

- `docs/clause_lexicon.json` — 出表程序读取

- `published/manifest.json` — 版本、出处、检索开通名单

## 七步对应操作

### 1. 定范围

改 `catalog.yaml` 里 `scope.answers` / `scope.does_not`。  
当前约定：回答「这句话是哪一条、和哪一条互斥、表格列是什么物理量」。  
当份规格书已给出相关量时，可用公式推算缺项。  
不回答「这条通常应该是多少」、不用库典型值填空。

### 2. 收源并分类

每来一份甲方材料，在 `catalog.yaml` 的 `sources` 加一条：`id`、名称、谁提供、密级、`leave_site`（出场所：一律 `false`，整库不出公网）。

### 3. 结构化（卡片）

- 清单条目：改 `docs/clause_lexicon.yaml` 对应 `id`（gloss、强/弱别名、exclude、cues、see、unverified）。  
- 企标：改 `enterprise_std.yaml`（定义、试验方法号、对照清单序号）。**`fill: false`**。评价看当份 DPR，不得把「通常」寿命或试验箱边界写入抽出值。  
- 物理：改 `physics.yaml`，写清 `law`、`use`（read_table / validate / derive）、**`fill: false`**。`derive: true` 才允许用当份原文里的量计算。  
  当前会算：\(R=U/I\)、\(P=UI\)、\(P=\sqrt{3}UI\)、\(T=9550P/n\)、\(I=P/U\)（升压直流）、\(I=P/(\sqrt{3}U)\)、\(t=RC\ln(V_0/60)\)、\(\eta=P_{out}/P_{in}\)、\(P_{loss}=P(1-\eta)\)。  
- 改完同步人读稿 `docs/清单与规格常见写法.md`（只增不删口径）。

### 4. 建索引

在本机执行（不上云、不做公网向量）：

```bash
cd /Users/wwj/电子电器项目/electrical-krow
python scripts/publish_knowledge.py
```

会重建关键词倒排索引，以及由 `see` / 禁配 / conflict / 物理卡片连成的图谱。  
近义目前用「别名折叠 + 弱别名索引」，不把规格书或库送到公网向量服务。

### 5. 确认后发布

`registry.yaml`：

- `default_status: draft` — 未确认，**不进选段检索**
- `confirmed` — 甲方已确认卡片，仍未开检索
- `published_retrieve` — 已确认且允许选段（现在只有耐电压 #14）

确认一条：把它的序号写入 `confirmed`，需要开检索再写入 `published_retrieve`，然后改 `version`，再跑 `publish_knowledge.py`。  
每次发布会在 `releases/<version>/` 留快照。

回滚：

```bash
python scripts/publish_knowledge.py --rollback 2026-09-03.1
```

### 6. 接到应用

出表已读 `docs/clause_lexicon.json`。命中条款时出处来自 `manifest.json` 的 `citation`（清单条目号 + 知识库版本）。  
程序不得把 `xlsx.example` 写进抽出值。当份原文已有电压/电流等输入量时，可以按公式推算缺项并标局部对应。

### 6a. 导出给公司知识库

公司知识中枢有两条轨（见同事《SimLab 领域包与编译：实现原理》）：**轨 A** 结构化知识包——仓外确定性编译器算出 `bundle.json`，治理台 `kind=bundle` 提案审批后整包 upsert 进空间；**轨 B** 文档编译——上传文档让 LLM 抽实体。我们的条款库走轨 A，空间 `compile_policy` 必须保持 `off`。发布之后在本机编译 + 导出：

```bash
python scripts/compile_kb_bundle.py           # 轨 A：bundle.json + domain_pack.json → docs/knowledge/export/<version>/
python scripts/export_kb_bundle.py            # ingest 三库用：records.jsonl + query_aliases.yaml（同目录）
python scripts/compile_kb_bundle.py --out /tmp/kb
```

轨 A 产物（`compile_kb_bundle.py`，零 LLM，同一真源重跑逐字节一致，只有 `version` 时间戳变）：

- `bundle.json` — 顶层 `id`（`electrical-xcm-clauses`，现场重导同 id 视为新版本：upsert + 删孤儿）/ `version`（编译时间戳，只做溯源）/ `space`（建议 `electrical`）/ `meta` / `entities` / `relations` / `wiki_pages`。
  - 实体四类：`CLAUSE`（116 条清单条目，id `clause:<序号>`，稳定号）、`PHYSICS_LAW`（35）、`STD_CLAUSE`（企标 45）、`TERM`（企标术语 12）。每条带 `names[]`（`ns` = list_name / alias_strong / alias_retrieve）、`identity`（全部 `distinct` / `rule`：序号唯一，不存在同名待裁定）、`definition`（= 当份 `gloss`，治理台词条「来源摘要」读这个）、`data`（治理字段）。保密企标不写释义。
  - **只有 `CLAUSE` 带 `category`**（对应 SimLab 只有 CAPABILITY 带功能域）：分类 SSOT 是脚本里的 `TAXONOMY`（清单 12 个分组，`order` 即侧栏顺序），层序只有 `list_group` 一层，封闭集合，未知分组直接报错，`uncategorized` 必须为 0。物理 / 企标 / 术语不带，走类型桶。
  - 关系六种：`related` / `not` / `same_slot` / `interprets`（来自 `published/graph.json`）+ `verifies`（企标条款 → 清单）/ `term_of`（术语 → 清单）。治理台字段是 `source_id` / `target_id` / `relation_type`（本仓同时写 `from` / `to` / `type`）。wiki 页同时写 `body`（= `content`）和 `source_id`（实体页=条目 id，essay=页 id）。
  - `wiki_pages`：每条 CLAUSE 一页（`page_type=entity`，frontmatter 带 `category`）+ 两篇 essay（条目索引、物理关系）。页面是图的投影，不是另一份真相。
- `domain_pack.json` — 薄 manifest，键集合卡死为 SDK `DomainPackManifest` 认的 8 个（多一个编译器拒绝写出）：`id=electrical`、`entity_kinds_extend`、`relation_kinds_extend`、`detection_keywords`、`ui_grouping`。它只给轨 B 做「这篇文档像电控」的识别开关，**不参与**分类、侧栏、bundle upsert。

ingest 产物（`export_kb_bundle.py`）：

- `records.jsonl` — 每行一条 Record：`kind`（clause / physics / enterprise_std / enterprise_term）、`title`、`symbol`、`source`、`content`、`payload`。
- `query_aliases.yaml` — 强别名（`hint`）与已开通选段的别名（`retrieve`）。**弱别名不导出**，下游不得补回。

两条产物线共用一套守门：`fill_from_kb=false`、`leave_site=false`；不带 `notes` / `split_harm` / `unverified` / `reject_patterns` / 弱别名；不带 `.insights`、`.krow`、合同双方称谓；已删除项不出现。保密一级来源（企标）只出条款号、标题、方法标准与清单对照，`cloud_generate=false`，对方作答链路见到这个标记不得把片段送云端模型。`compile_kb_bundle.validate()` 任何一条不过就不出包。

验收（对齐同事的出包门禁）：CLAUSE / PHYSICS_LAW / STD_CLAUSE / TERM / relations 计数与上一版比对，分类不应改变身份；`uncategorized=0`；schema VALID。导出目录不进 git，交付时整目录拷给对方。现场导入：`BUNDLE=bundle.json SPACE=electrical import-kg-bundle.sh`，建空间时 `compile_policy=off`；`PUT /v1/domain-packs/electrical` 登记 manifest 是可选项。

### 6b. 认条召回题集

`docs/knowledge/eval/clause_routing.yaml`：每题一句规格书里会出现的话，写明必须召回哪几条、不得召回哪几条，题源指向 `.insights/lessons/`。只评认条，不评取值。

```bash
python scripts/eval_knowledge.py            # 全部
python scripts/eval_knowledge.py --only 115 # 只跑涉及 #115 的题
```

本仓 `tests/test_knowledge.py::KnowledgeEvalTests` 每次回归都跑这份题集；把导出包交给公司知识库后，用同一份题集回归他们的检索层。`caution` 字段记录「检索层允许召回、出表规则必须排除」的条目，供对方对照，不做断言。新增复盘时若涉及认错列，同时补一题。

### 6c. 待专家口径标注

`docs/knowledge/pending_rulings.json`：值本身出自当份原文、但「怎么填 / 算不算正式指标」还没定的格子。出表时 `electrical/pending_rulings.py` 给命中的格子在「复核备注」末尾追加「待专家口径：…」（深红字）并在抽出值上加批注，「说明」页多一行合计。**不改抽出值，不改检索结论**（已检索到 / 未检索到 / 局部对应照旧）。

每条按核对表「需求序号」写：`items`、`when`（filled / empty / any）、`family`（省略 = 全部；dpr / inverter / generic）、`match`（正则，对抽出值+摘录）、`note`、`lesson`（必须指向 `.insights/lessons/` 里一篇，`electrical/tests/test_pending_rulings.py::ShippedFileTests` 会查）。

口径定下后：删掉该条 → 把结论落到 `electrical` 规则或黄金集 → 在复盘里记一笔。这里只放待定项，不放已定知识；也不得把 `note` 里的字写进任何格子的值。

### 6d. 工位页上的数字从哪来

工位页只展示数字，不展示条目内容，也不提供取值。嵌入（`?embed=1`）时只有出表页会显示，所以和出表相关的数字与历史都放出表页；工作台只留 SOR 出表一张卡。

- 出表页顶部一行「知识库版本 · 待专家口径 · 本账号已出 N 份 · 平均耗时」：`/api/health` 的 `knowledge`（`knowledge.knowledge_summary()`，版本 + 条款/物理/企标/分组数）与 `pending_rulings`（`pending_rulings.json` 条数）；份数、平均耗时来自 `/api/jobs`。
- 出表页底部最近核对表（出表进行中收起）、侧栏任务行：`output/jobs.jsonl` 每条完成记录多了 `pending_note`（带「待专家口径」的模板格数）、`groups`（按 `electrical.schema.item_group` 的 12 组三类结论）、`compare`（同名文件与上一份核对表逐条比已检索到：新增 / 减少）。旧记录没有这些字段，页面按空处理。
- 选中文件后的体检卡：`POST /api/inspect`（`inspect_doc.py`）只读文件头：PDF 页数与是否扫描件（每页原生字符 < 80，同 `read_doc`）、Word / Excel 不给页数；类型用 `electrical.doc_kind.classify_document`；预计耗时取本账号历史成功出表的中位数，优先同类型同介质，没有历史就不估。不落盘、不抽取。
- 出表中的「分段 n/N · 已抽出 k 项」：`electrical.progress.report_stats()`，`extract.py` 每批分段完成后上报；`jobs.py` 只在任务运行中更新 `chunk_done / chunk_total / filled`，不进历史。

### 7. 运维

抽错了按「一次代价 → 一篇复盘 → 一道闸门」结案，不要只改模型提示词。

1. **先召回**同主题复盘（读取侧，禁止半边墙）：

```bash
python scripts/recall_lessons.py 115
python scripts/recall_lessons.py 升压充电
```

2. 在 `.insights/lessons/` 按 `_TEMPLATE.md` 新增一篇，**必须**写清两行：
   - **反事实**：不这样改，下次会怎样错。
   - **二级依据**：清单 gloss / 专家格子（序号 + 印页 + 正确口径）/ 条款号。
   写不出这两行：交账本，不是交代码。
3. 判断改卡片还是改出表规则（认错列 → YAML；取值过满/过空 → `electrical` 闸门）。
4. 落下机器闸门（规则或 unittest）。没有闸门则复盘保持 `candidate`，不算结案。
5. 改 YAML / `physics.yaml` 后跑发布，并回归：

```bash
PYTHONPATH=. python -m unittest tests.test_clause_lexicon tests.test_knowledge tests.test_lessons
```

样例回归用专家认可的核对表冻结成的整表黄金（`electrical/examples/golden/dhts160_dpr.json`，116 行；状态必须一致、数字必须齐、页码不比）：

```bash
cd ../electrical
python -m electrical /路径/DHTS160_DPR.docx -o output/dhts160_回归.xlsx
python -m electrical.eval output/dhts160_回归.xlsx examples/golden/dhts160_dpr.json
```

新文档获专家认可后用 `python -m electrical.eval 认可.xlsx examples/golden/<doc>.json --freeze` 再冻结一份。  
`.insights`、`.krow`、wiki 与 `AGENTS.md` 不得写入抽出值。

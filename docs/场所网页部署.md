# 场所网页部署（指定场所内网）

与客户端共用一套 `electrical_krow` + `electrical` 流水线。员工用浏览器打开**场所内网 HTTPS**，规格书上传到场所应用机，识别打现场 Krow Server。规格书整文件不出公网。

网页端是否允许上传到场所服务器，须甲方书面确认，见 [双端交付口径.md](双端交付口径.md)。

## 本机先看一眼

不要和客户端窗口抢 18765。另开端口：

```bash
python -m electrical_krow site --port 18767
```

浏览器打开 `http://127.0.0.1:18767/`，标题旁应为「场所网页」，拖文件提示「上传到本场所服务器」。生产仍按下面 systemd + nginx 部署。

## 不要做

- 不要把规格书传到 `api.krow.cn`
- 不要把应用 `0.0.0.0` 直接暴露到公网
- 不要用手机号验证码登录本产品
- 不要把页面做成公网 SaaS

## 推荐拓扑

```
内网浏览器  --HTTPS-->  nginx（场所证书）  -->  127.0.0.1:18765 网关
                                              规格书落 ELECTRICAL_KROW_DATA
                                              分段 JSON --> 现场 Krow Server
```

应用默认仍绑回环。由 nginx 对内网提供 HTTPS。全站同时只跑一份出表（与协议「工位一份」一致），第二份会提示排队。

## 1. 机器与目录

一台场所 Linux 应用机（可与 nginx 同机）。

| 用途 | 建议路径 | 说明 |
| --- | --- | --- |
| 程序 | `/opt/electrical-krow` | 本仓库 |
| 出表流水线 | `/opt/electrical-krow/electrical` | 本仓库自带 |
| 数据盘 | `/var/lib/electrical-krow` | 上传缓存与核对表，设 `ELECTRICAL_KROW_DATA` |
| 配置 | `/opt/electrical-krow/config.ini` | 可从 `packaging/site/config.ini` 复制 |
| 证书 | `/etc/ssl/electrical-krow/` | 内网 CA 或场所证书，不要关校验 |

创建运行用户与数据目录：

```bash
sudo useradd --system --home /var/lib/electrical-krow --shell /usr/sbin/nologin electrical-krow
sudo mkdir -p /var/lib/electrical-krow /opt/electrical-krow
sudo chown -R electrical-krow:electrical-krow /var/lib/electrical-krow
```

把本仓库放到 `/opt`，用 venv 安装依赖。SOR 出表用仓库里的 `electrical/`，不必再单独放一份。

```bash
cd /opt/electrical-krow
python3 -m venv .venv
.venv/bin/pip install -e .
```

复制场所配置：

```bash
sudo cp packaging/site/config.ini /opt/electrical-krow/config.ini
```

编辑 `config.ini`：

- `delivery = site`
- `gateway_host = 127.0.0.1`（不要改成公网 IP）
- `server_url` = 现场 Krow Server 的 HTTPS 根地址（无尾斜杠、无 `/v1`）
- 如现场没有 `deepseek-v4-pro`，改 `chat_model`

不要把账号、密码写进配置文件。

## 2. systemd

```bash
sudo cp packaging/site/electrical-krow.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now electrical-krow
sudo systemctl status electrical-krow
```

服务以 `--no-browser --site` 启动，不自动开浏览器。

## 3. nginx HTTPS

样例：`packaging/site/nginx.conf.example`。

- 把 `sor.internal.example` 换成甲方内网域名
- `client_max_body_size 80m`（与上传限额一致）
- `proxy_read_timeout 3600s`（出表可能数分钟）
- 转发 `X-Forwarded-Proto`，以便登录 Cookie 在 HTTPS 下带 Secure
- 防火墙只放行场所内网访问 443

证书：公网 CA 或企业内部 CA 均可。企业内部 CA 须让场所浏览器信任，应用访问现场 Krow Server 时同样不要关闭证书校验；内网 PEM 写入 Python 信任链。

## 4. 现场切换识别地址

与客户端相同：只改 `config.ini` 的 `server_url`（及必要时 `chat_model`），然后：

```bash
sudo systemctl restart electrical-krow
```

联调可暂用契约验证地址；生产必须切到现场 Krow Server。

## 5. 验收

内网打开 `https://sor.internal.example/`（以甲方域名为准）：

1. 同一套邮箱 + 密码能登录（不要手机号）
2. 页面文案为「场所网页 / 上传到本场所服务器」，不是「本机读取」
3. 上传一份真实规格书，能下载核对表
4. 第二人同时提交时应提示「全站同时一份」、请排队
5. 规格书文件出现在 `/var/lib/electrical-krow`，而不是传到公网

抽查同一份规格书，与客户端核对表口径一致。

扫描件 PDF 需要场所机安装 Tesseract（`chi_sim` + `eng`）。是否纳入本期验收，须双方书面确认。

## 6. 可选：Docker

样例：`packaging/site/docker-compose.yml`。容器用 `network_mode: host` 绑 `127.0.0.1:18765`，仍须在宿主机用 nginx 做内网 HTTPS。不要把 18765 映射到公网。

生产优先用上面的 systemd，Docker 仅在甲方明确要求容器时使用。

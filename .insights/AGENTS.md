# 电控工位 · 知识治理（.insights）

一次代价 → 一篇复盘 → 一道机器守着的闸门。  
复盘进 `.insights/lessons/`，条款进 wiki 锚定的 YAML，抽出值只来自当份材料。

`.insights` 是**变动的项目**：认错列、取值过满、易混复盘都写在这里。  
相对不变量在 wiki（`docs/knowledge/` 已确认卡片与发布产物；SDK 编译页在 `.krow/wiki`）。  
治理时两者一起用：wiki 回答「这条是什么」，insights 回答「上次为什么认错」。  
`.krow` 只负责 agent 自进化，不放业务复盘。

## 红线

1. **认条 ≠ 取值。** 知识库只回答「这句话是清单哪一项、和谁互斥、公式能不能用」。抽出值只能是当份原文，或当份已出现的量按已确认公式算出的缺项。
2. **`fill_from_kb` 恒为 false。** 禁止用清单示例、库典型值、insights、AGENTS.md、wiki、Ontology definition 填核对表。当份未给出、条目需参考试验方法标准时，抽出值仍未检索到，方法号只写复核备注；禁止写企标举例寿命或试验箱边界，也禁止把「参考 标准号」写入抽出值。
3. **不 `agent.run()` 开放规划。** 工位路径预先编排：读文档 → 分流 → 文件质检（可交叉知识库主题，对照当份中英与内部逻辑，不填格）→ 规则先填 → 空缺项分段 JSON → Excel。
4. **未确认不开检索。** `registry.yaml` 默认 draft；甲方确认后才 `confirmed`；别名验证过才 `published_retrieve`。
5. **禁止半边墙。** 只写复盘不改闸门、只改提示词不改卡片/测试、只注入检索不注入约束，都不算结案。

## 抽错结案（写入强制）

修认条或出表规则时，必须在 `.insights/lessons/` 新增一篇，且写清两行：

- **反事实**：不这样改，下次会怎样错。
- **二级依据**：清单 gloss / 专家格子（序号+页码+正确口径）/ 条款号。

写不出这两行：交账本，不是交代码。  
没有对应测试或规则闸门：复盘未完成。

## 读取（机制送达）

改卡片或出表规则前，先召回同主题复盘：

```bash
python scripts/recall_lessons.py 115
python scripts/recall_lessons.py 升压充电
```

召回只避免重复踩坑，不填抽出值。没有命中也可以改，结案仍须新写一篇。  
修 bug 不先搜同主题历史，就是半边墙。

## 分层

| 层 | 写什么 | 不写什么 |
| --- | --- | --- |
| wiki（`docs/knowledge/`，相对不变量） | 确认后的语义、别名、禁配、公式、方法号 | 抽出值、摩擦过程 |
| `.insights/lessons`（变动） | 摩擦复盘 | 规格书数字、已确认口径（那是 wiki 的事） |
| `.krow` | agent 自进化落盘 | 业务认条复盘 |
| 出表规则/测试 | 机器闸门 | 用库补空 |
| 客户 PRD/架构 | 经甲方确认再改 | 把场所网页写进架构 |

客户文档（`docs/产品需求与设计.md`、`docs/技术架构.md`）未经明确要求不要改。

## 价值观（冲突时）

准确性 > 完整性 > 速度 > 成本。  
宁留空并标未检索到，也不用常识补格。过满标成已检索到，比漏填更差。
